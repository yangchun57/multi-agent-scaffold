# 安全编码规范 · 概述

> 基于 Code Review 发现的 C-1、H-1~H-4 等问题提炼。

## 适用范围

本规范适用于所有涉及认证授权、文件上传、接口访问控制的代码。

## 核心原则

1. **最小权限原则**：所有管理接口必须显式标注 `[Authorize]`，默认拒绝未授权访问
2. **纵深防御原则**：前端校验 + 后端校验 + 数据库约束三层防护
3. **零信任原则**：所有外部输入（文件、参数、Header）均需校验和过滤
4. **安全默认原则**：配置项缺失或无效时，应用应拒绝启动而非降级运行

## 问题分类

| 级别 | 说明 | 示例 |
|------|------|------|
| Critical | 可直接导致权限提升、数据泄露 | 管理接口无授权、JWT 密钥过短 |
| High | 可被利用但需要特定条件 | 文件上传无类型校验、无限流 |
| Medium | 潜在风险但利用难度较高 | HTTP 状态码被掩盖 |

## 强制检查清单

- [ ] 所有 Controller 方法是否标注 `[Authorize]` 或 `[AllowAnonymous]`
- [ ] JWT 密钥长度是否 ≥ 256 位
- [ ] 生产环境是否强制 HTTPS
- [ ] 文件上传是否校验大小和类型
- [ ] 公开接口是否配置速率限制
