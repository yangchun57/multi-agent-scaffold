# 移动端开发规范_v1.0 · 第 10 章 构建、发布与资源管理

> 拆分自《移动端开发规范_v1.0》第 11 节。需要全量上下文时读原文件。


### 原则

构建可切换、资源受控、双端一致。编译时开关切换模式、构建脚本统一产物、资源与版本受控、双端差异文档化，让发布可重复、仓库不膨胀。

### 抽象规则

- 编译时开关 `MUST` 用 `dart-define`（如 `USE_MOCK`）。
- Release 产物 `MUST` 有统一构建脚本与固定输出目录。
- iOS/Android 双端差异（签名、平台原生配置）`MUST` 文档化。
- 版本号 `MUST` 语义化（`pubspec.yaml` 的 `version`）。
- 资源 `MUST` 在 `pubspec.yaml` 的 `assets` 注册。
- 单文件 `MUST` 小于代码托管平台硬限（如 100MB）；超限 `MUST` 用 LFS 或不入库。
- 二进制模型/大资源 `SHOULD` gitignore，手动放置并文档化。

### 代码示例

`pubspec.yaml` 资源注册 + 语义化版本：

```yaml
name: my_app
version: 1.0.0+1    # 语义化：name.version+buildNumber

environment:
  sdk: ^3.12.2

flutter:
  uses-material-design: true
  assets:
    - assets/mock_data/
    - assets/images/
    - assets/models/      # 二进制模型 gitignore，目录仍注册
```

构建脚本（带编译时开关）：

```bash
# Mock 演示模式
flutter build apk --release --dart-define=USE_MOCK=true
# 真实 API 模式
flutter build apk --release
# iOS
flutter build ipa --release --dart-define=USE_MOCK=true
```

`.gitignore` 策略（二进制模型不入库）：

```
assets/models/*.onnx
```

### ⛔ 反模式

- 大文件直入库--仓库膨胀、克隆失败
- assets 未注册--运行时资源缺失崩溃
- 版本号随意--发布追溯困难
- 二进制模型入库--仓库膨胀、更新困难
