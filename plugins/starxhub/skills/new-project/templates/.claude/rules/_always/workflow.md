# 工作流程规范

## 核心原则
1. **需求先行**：先有需求文档，再进入设计
2. **设计先行**：先有架构设计，再编写代码
3. **契约先行**：先定义接口契约，再实现细节
4. **测试兜底**：所有代码必须有对应测试

## 标准开发流程
```
需求分析 → 架构设计 → 接口契约 → 数据库设计 → 编码实现 → 代码审查 → 测试验证
```

## 文档落盘要求
- 需求文档：`docs/requirements/`
- 设计文档：`docs/design/`
- 接口契约：`docs/api/`
- 数据库设计：`docs/database/`
- 变更记录：`docs/changelog/`

## Agent 协作规范
- 每个 Agent 完成工作后，必须将产出物落盘到对应目录
- 下游 Agent 通过读取文档获取上下文，不依赖口头传递
- 使用 `/review` 命令触发代码审查流程
