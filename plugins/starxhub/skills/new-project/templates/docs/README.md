# 文档管理规范

> 版本：v2.1 ｜ 2026-09-03 ｜ 本文件保持 Markdown 格式（目录入口用 md，便于任何环境直接阅读与检索）

## 一、目录结构总览

```
docs/
├── README.md               ← 本规范（目录入口，Markdown）
├── common.css              # 全站共享样式（唯一样式来源，HTML 文档内禁止内嵌 style）
├── md2html.py              # Markdown → 模板 HTML 批量转换器
├── 00-项目文档/             # Agent 读写的工作文件（Markdown，见第四节）
├── 01-方法论调研/           # 交付物：调研报告（HTML）
├── 02-多Agent最佳实践/      # 交付物：指南（HTML）
├── 03-最佳实践手册/         # 交付物：操作手册（HTML）
└── _模板与规范/             # 模板与图标速查（下划线前缀，不参与业务交付）
    ├── README-规范说明.md   # HTML 生成规范全文
    ├── 模板-裸HTML.html     # 可复制的空白模板（含全部组件示例）
    └── 图标速查表.html       # 164 个 Ant Design 内联 SVG 图标
```

**双轨制说明**：docs/ 下同时存在两种格式——人读的**交付物**用 HTML（统一视觉、可分享），Agent 读写的**工作文件**用 Markdown（易编辑、命令引用稳定）；目录入口 README 用 Markdown（任何环境直接可读）。

## 二、文件夹命名及编号原则

1. 文件夹编号格式为 `<两位序号>-<中文或英文简称>`，序号按一级目录递增，如 `01-方法论调研`、`02-多Agent最佳实践`。
2. 二级文件夹在父编号后追加子序号，用下划线连接，如 `02-设计文档` 下的 `02_01-概要设计`。
3. 文件夹名称使用中文或英文简称，不含空格和特殊字符（仅允许字母、数字、中文、下划线和连字符）。
4. 编号一旦分配不得变更；新增文件夹追加末尾序号；废弃文件夹保留编号并加 `_deprecated` 后缀，不得删除或重用编号。
5. **00 号约定**：`00-xxx` 是"项目自身默认内容"（如 00-项目文档），01/02 起才是"额外产出的交付物"——项目自身内容不与交付物混排流水号。
6. 下划线 `_` 开头的文件/文件夹为辅助资源（模板、规范、工具），不视为业务文档。

## 三、文档命名及编号原则

1. 文档编号格式为 `<所属文件夹编号>-<三位流水号>`，如 `01-001` 表示 01-方法论调研 下第 1 篇。流水号在同级文件夹内唯一递增，不得重用。
2. 文档完整命名格式：

   ```
   <文档编号>_<文档简称>_v<版本号>_<时间戳>.<扩展名>
   ```

   示例：`01-001_敏捷开发与Scrum_v0.1_20260814_101549.html`

3. 文档简称用中文或英文，不含空格；版本号语义化（v0.1 迭代 / v1.0 重大修订）；时间戳 `YYYYMMDD_HHMMSS` 精确到秒。
4. 修订时复制原文件并递增版本号与时间戳**重命名**，保留历史版本，不得覆盖旧版本。
5. 扩展名按用途：`.html`（交付物）、`.md`（README 入口与 Agent 工作文件）。

## 四、文档格式双轨制：HTML 交付物 + Markdown 工作文件

| 类别 | 格式 | 位置 | 理由 |
|------|------|------|------|
| 目录入口（本文件） | **Markdown** | `docs/README.md` | 任何环境直接可读、检索友好 |
| 交付物（调研报告、指南、说明） | **HTML** | 01-方法论调研/、02-多Agent最佳实践/ | 统一视觉规范、浏览器直读、可分享 |
| Agent 工作文件（需求、计划、变更记录） | **Markdown** | 00-项目文档/ | Agent 读写高效、命令路径引用稳定（11 个 Agent + 7 个命令全部引用 md 路径）、版本 diff 友好 |

### 格式转换

Markdown 转 HTML 用目录下的转换器，输出自动符合第五节模板规范：

```bash
python md2html.py <输入.md> <输出.html> [标签] [css相对路径]
# 示例：子目录文档用 ../common.css
python md2html.py "01-方法论调研/01-001_xxx.md" "01-方法论调研/01-001_xxx.html" "方法论调研" "../common.css"
```

> 注意：00-项目文档/ 保持 Markdown **不转换**——它是多 Agent 系统的通讯载体，转 HTML 会破坏 Agent 写作流与全部命令引用。

## 五、HTML 文档统一模板

所有 HTML 交付物遵循 `_模板与规范/README-规范说明.md` 的完整规范，核心要点：

1. **裸 HTML 原则**：`<head>` 只引一个 `common.css`（子目录用相对路径 `../common.css`），禁止内嵌 `<style>`、禁止任何 CDN。
2. **结构骨架**：所有内容在 `.wrap` 内；`.hero`（标题区）→ `.toc`（目录锚点）→ `section.sec`（章节，配 `.num` 数字徽章与 id 锚点）。
3. **组件库**：提示框 `.box.tip/.warn/.error/.info`、表格、代码块 `pre` / `code.inline`、结论框 `.verdict`、徽章 `.badge`、步骤流 `.steps`——全部由 common.css 提供。
4. **图标**：Ant Design 内联 SVG（`class="icon"` + `fill="currentColor"`），零外部依赖；查图标用 `_模板与规范/图标速查表.html`。
5. **写作约定**：标题层级 hero h1 → sec h2 → h3；结论先行；对比与清单优先表格；**禁用 emoji**（图形语义一律用图标）。

## 六、质量检查清单

每份 HTML 文档生成 / 转换后自检：

- [ ] `<head>` 只有 common.css 一个样式引用；无内嵌 `<style>`、无 CDN 链接
- [ ] 所有内容在 `.wrap` 内；每个 section 有 id 且与目录锚点一致
- [ ] 图标全部为内联 SVG，含 `class="icon"` + `fill="currentColor"`
- [ ] 无 emoji；配色只用 CSS 变量语义色，未写死颜色值
- [ ] 文件名符合 `编号_简称_v版本_时间戳.html`；修订走"复制 + 递增版本"，未覆盖旧版
- [ ] 响应式：窄屏（≤720px）下表格、代码块、头图不溢出
- [ ] 00-项目文档/ 下没有误放 HTML；01/02 目录下没有误放 Markdown
