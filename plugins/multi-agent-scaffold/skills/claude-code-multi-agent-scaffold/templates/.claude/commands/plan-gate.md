description: 方案放行门禁（风险扫描 + 三重校验），编码前的强制闸门
---

**编排原则**：门禁是两个角色工作，必须分别启动 SubAgent，不要内联在主 Agent 做。主 Agent 只负责串联、传递产物路径、汇总结论。

请对当前已产出的架构方案执行放行门禁，判定是否允许进入编码阶段。

## 第一步：主 Agent 定位方案产物

检查并确定以下产物的实际路径（不存在则立即终止并报告）：

| 产物 | 期望位置 | 必需性 |
|---|---|---|
| 架构设计 | `docs/00-项目文档/` 下架构相关文档 | 必需 |
| 接口契约 | `api-contracts.md` | 涉及接口时必需 |
| 数据库设计 | `database-design.md` | 涉及数据时必需 |
| 需求产物 | `requirements.md` 或需求文档 | 必需 |

任一必需产物缺失 → 直接输出 `REJECT（产物缺失）`，不启动 SubAgent。

## 第二步：启动 plan-risk-analyst SubAgent

传递：方案产物路径清单、对应需求产物路径。

要求它按 R1→R7 顺序扫描，重点关注**多租户红线（R4）** 与 **AI 易漏的异常边界（R6）**。

## 第三步：启动 plan-gatekeeper SubAgent

传递：方案产物路径清单 + 上一步的风险扫描报告完整内容。

要求它按 C1→C2→C3 独立判定并输出放行结论。

## 第四步：主 Agent 汇总并执行门禁

按判定结果处理：

| 结论 | 主 Agent 动作 |
|---|---|
| **PASS** | 汇报放行，允许进入编码阶段 |
| **CONDITIONAL PASS** | 逐条列出放行条件，**逐条确认后才放行**；条件未确认完不得进入编码 |
| **REJECT** | **停止流程，禁止进入编码阶段**。把阻塞项 + 修复任务清单交给 architect，要求修订后重新执行 `/plan-gate` |

任一结论下，若发现**多租户红线相关阻塞项**，一律按 REJECT 处理，**不允许降级为 CONDITIONAL**。

## 输出格式

```markdown
# 方案门禁结果

判定：PASS / CONDITIONAL PASS / REJECT
风险扫描：阻塞 {n} 条 / 建议 {m} 条
门禁校验：C1 {结论} | C2 {结论} | C3 {结论}

## 阻塞项（必须修复）
| # | 来源 | 位置 | 问题 | 修复任务 |
|---|---|---|---|---|

## 放行条件（CONDITIONAL 时必填）
- [ ] 条件1

## 下一步
（按结论给出明确指令）
```

## 禁止事项

- 不跳过任一 SubAgent，主 Agent 不内联做门禁判断
- 不在 REJECT 时继续推进后续步骤
- 不修改任何代码或文档（修复由 architect 等执行者完成）
- 不因"看起来差不多"而放行 —— 判定以 plan-gatekeeper 的结构化结论为准
