# 移动端开发规范_v1.0 · 第 2 章 导航与路由

> 拆分自《移动端开发规范_v1.0》第 3 节。需要全量上下文时读原文件。


### 原则

路由集中注册，路径可读自解释，Tab 页状态可保持。统一的导航结构让页面跳转可预测、可深链，且 Tab 切换不丢状态。

### 抽象规则

- `MUST` 用命名路由：集中定义路由常量 + `routes` Map 注册，`MUST NOT` 硬编码路径字符串。
- 路径 `MUST` 用 kebab-case（`/domain/action` 或 `/domain/action-sub`）。
- Tab 容器 `MUST` 用 `IndexedStack` 保持各 Tab 页面状态；`MUST NOT` 用无保状态的 `PageView` 承载需保持状态的 Tab。
- 独立页面（非 Tab）`MUST` 用 `Navigator.push`，不进 Tab 栈。
- `MUST` 设独立启动页为初始路由（如启动屏/引导页），`MUST NOT` 将初始路由直连业务页。
- 新增路由 `MUST` 三步：加路由常量 -> 注册到 `routes` Map -> 实现 Widget。

### 代码示例

命名路由集中注册：

```dart
class AppRoutes {
  static const String home = '/';
  static const String splash = '/splash';
  static const String itemDetail = '/item/detail';

  static Map<String, WidgetBuilder> get routes => {
        home: (_) => const MainShell(),
        splash: (_) => const SplashPage(),
        itemDetail: (_) => const ItemDetailPage(),
      };
}
```

Tab 容器用 `IndexedStack` 保持状态：

```dart
class MainShell extends StatefulWidget {
  const MainShell({super.key});
  @override
  State<MainShell> createState() => _MainShellState();
}

class _MainShellState extends State<MainShell> {
  int _index = 0;
  final List<Widget> _pages = const [
    HomePage(),
    LibraryPage(),
    ProfilePage(),
  ];

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: IndexedStack(index: _index, children: _pages),
      bottomNavigationBar: BottomNavigationBar(
        currentIndex: _index,
        onTap: (i) => setState(() => _index = i),
        items: const [
          BottomNavigationBarItem(icon: Icon(Icons.home), label: '首页'),
          BottomNavigationBarItem(icon: Icon(Icons.library_books), label: '库'),
          BottomNavigationBarItem(icon: Icon(Icons.person), label: '我的'),
        ],
      ),
    );
  }
}
```

### ⛔ 反模式

- 硬编码路径字符串散落各处--改路由需全文搜索
- 深嵌套 push 栈--难返回、难深链
- Tab 用 `PageView` 无保状态--切回 Tab 状态丢失
- 初始路由直连业务页--跳过启动/登录流程
