# 通用开发规范 · 九、代码审查清单

> 拆分自《通用开发规范》第 9 节。需要全量上下文时读原文件。


### 9.1 Controller 审查

- [ ] 路由是否规范（RESTful 风格）
- [ ] 权限特性是否正确配置
- [ ] 参数校验特性是否完整
- [ ] 是否返回统一格式的 ApiResult
- [ ] 是否正确使用异步方法
- [ ] 是否有完整的 XML 文档注释
- [ ] 查询前是否调用 `request.Normalize()`

### 9.2 Service 审查

- [ ] 是否通过接口注入依赖
- [ ] 返回值是否使用元组模式 `(bool Success, string Message, T? Data)`
- [ ] 事务是否正确使用
- [ ] 是否有足够的日志记录
- [ ] 是否正确使用 async/await

### 9.3 前端组件审查

- [ ] 组件命名是否符合规范
- [ ] Props 和 Emits 是否使用 TypeScript 类型
- [ ] 样式是否使用 scoped
- [ ] 是否有未使用的导入
- [ ] 是否正确处理 loading 状态
- [ ] 表单是否使用 `ref<FormInstance>()`
- [ ] 引入顺序是否正确

### 9.4 类型审查

- [ ] 类型定义是否完整
- [ ] 是否避免使用 any
- [ ] 枚举是否同时定义 Label 和 Type

### 9.5 数据库审查

- [ ] 表名是否符合规范（小写下划线）
- [ ] 是否包含 created_at 和 updated_at 字段
- [ ] 可空字段是否使用 `?` 和 `IsNullable = true`
- [ ] 主键是否正确配置

### 9.6 安全审查

- [ ] 敏感数据是否加密存储
- [ ] 密码是否使用 BCrypt 哈希
- [ ] 是否有越权访问风险
- [ ] 输入是否经过校验和清理

### 9.7 关键规则新增/强化时的存量代码审计（强制）

当在 CLAUDE.md、开发规范等文件中**新增或强化**某条规则时，必须在**同一次 PR** 中完成以下动作：

1. **存量扫描**：用 Grep/Glob 全仓搜索已违反新规则的历史代码
2. **统一整改**：将存量违规一并修复（代码 + 注释），不留遗留
3. **审查确认**：code review 时检查「新规则 + 存量审计」是否同 PR 完成

**禁止**规则确立后遗留历史违规，导致后续开发者误以为存量代码是正确示范。

> 来源：SYSTEM 哨兵大小写规则已在 CLAUDE.md 明确，但 `DeviceService.SystemTenant = "system"` 等 3 处代码 + 5 处注释仍用小写，直到审计整改才暴露。
